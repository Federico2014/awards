# 参与指南

[English](../../CONTRIBUTING.md)

仓库依据孙宇晨奖修订版框架初始化，完整 v0.8 制度和候选记录仍待导入。参与用于建立公开证据记录，提交 Issue 本身不构成授奖公示。

## 四类参与方式

| 类型 | 应提交的信息 | 处理方式 |
| --- | --- | --- |
| 推荐问题 | 准确陈述、意义、原始资料、已知结果、形式化链接 | Curator 检查范围与重复项，决定是否建立观察记录。 |
| 推荐获奖人 | 获奖人占位符或已确认公开 ID、贡献拆分、证据、关联条目、归属疑点 | Curator 补充归属证据并安排独立审查。 |
| 纠错 | 具体记录或文档、原文、建议更正、依据 | 暂由策展委员会处理，实质性更正须委员会确认。 |
| 争议申诉 | 条目或决定、争议主张、证据、期望结果、利益冲突 | 依第九章适用 30 日窗口，由未参与原评定者复核并公示结论。 |

使用对应 [Issue 表单](../../.github/ISSUE_TEMPLATE/)，优先关联已有讨论。利益冲突仅披露必要的公开职务信息。书面确认前，文件、Issue 和提交消息一律使用 RECIPIENT-<ENTRY>-A 等占位符；不得公开未经确认的姓名、邮箱、地址、身份材料、支付信息、内部评定底稿或供应商信息。

## 处理流程

1. 策展委员会检查完整性、重复项、公开证据、隐私和相关性，必要时要求补证。公众提交的常设责任人仍待制度设立，框架暂由委员会承担。
2. 记录利益冲突及回避。接受评定的推荐进入相应候选池；现行评级制度仅覆盖已解决题目，不新增未解决题目的挂榜或定价流程。
3. 进入 `under-verification` 时冻结制度版本、正文提交及业务事件日期。获奖人书面确认前保持占位符；主张形式化通道时在候选阶段即须提供钦定陈述。
4. 完成独立核验及归属审查。待获奖人确认的条目仍留在候选池；仅在核验完成且书面确认后，移入真实授奖批次并以 `status: announced` 公示。
5. **采纳与不采纳均须在原 Issue 公开答复决定和理由并归档**，不能不作说明就关闭。
6. 正式异议仅通过 dispute Issue 表单提交。按第九章适用 30 日窗口，具体起算对照正式制度；复核者不得参与原评定，结论须公示。Discussions 仅供一般咨询，不构成正式异议提交。
7. 撤销时在原授奖旁追加日期、触发条件、中英文理由、完整证据及核验失效点。原等级、获奖归属和核验材料保留，不通过删除历史授奖表示撤销。

详见[记录指南](records.md)及 [Discussions 说明](discussions-notice.md)。完整制度仍待导入，本指南不代拟缺失的时限、评分门槛或付款条件。

## Pull Request

- 保持中英文一致，说明翻译疑点。
- 使用[记录指南及模板](records.md)，不要把示例成果放进真实候选或授奖目录。
- 提供公开证据和状态变更理由；新授奖须有公开公示、完成的核验、获奖人书面确认、已确认公开档案及明确批次成员关系。
- 先改源记录，再验证并生成汇总，在同一 PR 提交 JSON 变化。
- 完成 PR 检查清单。自动化检查只约束结构，不证明证据真实性或治理决定有效。
